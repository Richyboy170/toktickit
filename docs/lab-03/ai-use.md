## 2. My Reflection

The specification work turned the handout into a concrete contract: three roles, server-established identity, an eight-hour opaque session cookie, a first-login password guard, ownership rules, a small status matrix, and separate Public Comment and Internal Note resources. The coding work then carried those decisions through Prisma migration, scrypt password handling, role middleware, Requester regression, Staff Queue and Detail screens, and Administrator User Management. I accepted the preserved integer IDs and a local post-migration initializer for legacy rows because they keep existing Ticket and Attachment relationships intact without putting a password in SQL or source control. Review was necessary. A read-only pass caught that the old requester header and selector could still be used, that some roles landed on the wrong page, and that the first status UI sent confirmation automatically. Those findings led to an explicit compatibility flag, role-safe redirects, voluntary password changes, valid-next-state options, and confirmation before consequential transitions. Local client tests, server Lab 3 boundary tests, builds, and Prisma validation pass. PostgreSQL is unavailable on this machine, so database-backed regression, migration, seed, API integration, browser, screenshots, peer review, and GitHub CI evidence remain pending. I have kept those limits visible instead of treating generated plans or agent reports as completion evidence.
