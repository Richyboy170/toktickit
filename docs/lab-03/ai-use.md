## 2. My Reflection

The specification work turned the handout into a concrete contract: three roles, server-established identity, an eight-hour opaque session cookie, a first-login password guard, ownership rules, a small status matrix, and separate Public Comment and Internal Note resources. The coding work then carried those decisions through Prisma migration, scrypt password handling, role middleware, Requester regression, Staff Queue and Detail screens, and Administrator User Management. I accepted the preserved integer IDs and a local post-migration initializer for legacy rows because they keep existing Ticket and Attachment relationships intact without putting a password in SQL or source control. Review was necessary. A read-only pass caught that the old requester header and selector could still be used, that some roles landed on the wrong page, and that the first status UI sent confirmation automatically. Those findings led to an explicit compatibility flag, role-safe redirects, voluntary password changes, valid-next-state options, and confirmation before consequential transitions. Peer review caught the Administrator Staff Detail read guard mismatch and later the missing Issue linkage on PR #41; both were corrected before approval. Local client tests, server Lab 3 boundary tests, builds, Prisma validation, and fixture-backed UI capture pass. Final-main GitHub Actions run 35311307446 then passed the full database-backed server and client suites, Playwright workflow, visual capture, and artifact upload on commit `161ddd8`. PostgreSQL remains unavailable on this workstation, so local database cases are still reported as blocked rather than misrepresented. The 18 UI captures are labelled as fixture-backed, while artifact 10533875135 supplies database-backed browser evidence. Keeping those boundaries visible—and requiring immutable GitHub evidence before claiming completion—was the main lesson from using the agents.
